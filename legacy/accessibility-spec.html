companion mode spec

Accessibility.

Three companion modes.

The standard system already meets WCAG AA at every text combination and AAA on the primary graphite scale. Accessibility is the baseline, not a mode. These three companion switches — Larger text, High contrast, Reduced motion — extend that baseline for users who need more than compliance.

They are independent toggles that combine freely with each other and with dark mode. Sixteen possible states; four of them need explicit spec.

01 — position

Four principles.

Companion modes are additive infrastructure — they layer on top of a system already designed for accessibility, not compensating for a system that isn't.
01

Baseline first.

The standard light and dark systems already meet WCAG AA at every combination and AAA on the primary graphite scale. Cobalt at 8.4:1 AAA in light, 7.8:1 AAA in dark. Companion modes are not fixes for a broken baseline — they are extensions for users whose needs exceed compliance.

02

Three independent toggles.

Larger text, High contrast, and Reduced motion are separate switches. Not one bundled "accessibility mode." A user with presbyopia may want larger text but no contrast change. A user with a vestibular disorder wants reduced motion regardless of text size. Bundling them forces false choices.

03

Honor system preferences first.

OS-level preferences — prefers-reduced-motion, prefers-contrast, browser text zoom — take effect automatically on first paint. Users who set these at the system level should not have to re-enable them per site. Manual toggles override system pref for site-specific choice.

04

Persist explicit choice.

Once a user picks manually, that choice persists in localStorage across sessions. System preference is the default; explicit toggle wins. This matters because users adjust their setup for the specific task — a designer might reduce motion when reading long-form case studies but not when browsing visual work.

02 — larger text

Larger text.

Serves users with low vision, presbyopia, small-screen contexts, or reading fatigue. Body-oriented sizes scale by 1.2×; display type stays fixed because it is already large.

The core insight: users who need larger text need it for reading. Body 16 to body 19 is a real gain. Hero 72 to hero 86 is invisible — the display was already large enough. Scaling everything uniformly wastes vertical space and pushes content off the fold without benefit.

03 — high contrast

High contrast.

Serves users with low-vision conditions, some color-blindness edge cases, and glare-heavy environments. The graphite scale shifts up one stop; structural borders thicken; subtle washes are removed.

The system already runs AAA on primary text. High contrast mode targets secondary text — the 70 and 50 stops that are AA-large-only — by shifting them up to their next-darker sibling. Every visible text element becomes AAA at any size.

Token shift — light mode

Role Normal High contrast Verified
Body text (gr-85)#3B3B3F · 10.5:1#1A1A1F · 16.3:1AAA
Secondary (gr-70)#5D5D60 · 6.2:1#3B3B3F · 10.5:1AAA
Meta (gr-50)#89898A · 3.3:1#5D5D60 · 6.2:1AAA

Cobalt does not shift. At 8.4:1 it is already AAA and reads as decisive against Snow. Changing it would break brand recognition without accessibility gain.

Structural changes beyond color

  • Card borders thicken from 0.5px to 1px. Borders become load-bearing, not decorative.
  • Focus rings thicken from 2px to 3px. The current 2px reads clearly at AA; 3px reads unmistakably at any vision level.
  • Cobalt-wash backgrounds (pills, callout surfaces) drop to 0px width — the wash becomes transparent and pills rely on their cobalt text + 1px cobalt border for definition.
  • Underline treatment on links becomes always-on (removes hover-only underlines).
  • Image containers gain a 1px stone border. Media that previously floated on Snow now has a clear boundary.
Dark mode + high contrast

Dark high-contrast follows the same principle in the inverted direction: gr-85 shifts up to gr-100, borders thicken to Stone dark at 1px, washes drop out. See §5 for the combined state matrix.

04 — reduced motion

Reduced motion.

Serves users with vestibular disorders, ADHD, migraine sensitivity, and anyone doing focused work who finds movement distracting. Every transition collapses to instant; nothing else changes.

What zeros

Every duration in the system is expressed as either var(--dur-micro) (200ms) or var(--dur-page) (350ms). Reduced motion overrides both to 0ms. All hover states, page transitions, scroll reveals, and micro-interactions become instant.

@media (prefers-reduced-motion: reduce) {
  :root {
    --dur-micro: 0ms;
    --dur-page:  0ms;
  }
}

[data-motion="reduced"] {
  --dur-micro: 0ms;
  --dur-page:  0ms;
}

What stays

  • Easing curves. var(--ease) still applies — at 0ms it is invisible, but keeps the code path consistent between modes.
  • Sequencing logic. Elements still fade in on scroll — just instantly. The appearance logic is preserved; only the animation is removed.
  • Focus rings. Reduced motion never affects focus visibility. If anything, focus rings become more important because users cannot rely on animated confirmation of state changes.
  • Loading indicators. A spinner or progress state is essential UX information, not motion decoration. Loaders remain animated even in reduced-motion mode. If a loader could be replaced with a static "Loading..." label, use the label instead.
Boundary case — auto-playing video

Case study cover videos, background loops, and marquee-style animations must not auto-play in reduced motion. Replace with a static poster frame and a manual play button. This is a WCAG 2.1 Success Criterion (2.3.3) and non-negotiable.

05 — combined states

When modes combine.

Four independent toggles yield sixteen possible states. Twelve of them need no special handling — CSS variables cascade correctly. Four combinations need explicit spec.

The four toggles

AttributeValuesSource
data-theme"light" | "dark"manual / prefers-color-scheme
data-text"normal" | "larger"manual / browser zoom
data-contrast"normal" | "high"manual / prefers-contrast
data-motion"normal" | "reduced"manual / prefers-reduced-motion

Combinations requiring explicit rules

State Behavior
Dark + High contrast gr-85 → gr-100 (in dark), Stone dark thickens to 1px, cobalt-wash drops to transparent. Cobalt Lifted stays at #8FA2EE.
Dark + Larger text Standard body 19 on dark bg = same 13.4:1 as body 16 (color is what matters, size doesn't affect ratio). Verify only that display sizes remain visually balanced when body text grows.
High contrast + Larger text Compounds: gr-85 becomes gr-100 (16.3:1) AND body 16 becomes body 19. Text becomes maximally legible. No conflict.
All three enabled Maximum accessibility state. Larger text + high contrast + reduced motion. Design must remain functional here — this is the state to test against, not an edge case.

The other twelve — no special handling

The remaining twelve states inherit correctly because CSS custom properties cascade through the token layer. When larger text is enabled in dark mode, the type sizes swap but colors stay in the dark scale. When reduced motion is enabled with high contrast, motion zeros but colors shift independently. Each toggle owns its own token scope and does not interact with others structurally.

Testing rule

Every new component must be validated in three states minimum: baseline light, baseline dark, and all-three-enabled maximum accessibility. If it works in those three, it works in the other thirteen.

06 — implementation

Implementation.

Additions to tokens.css and one React hook that manages all four preferences.

tokens.css — companion mode additions

/* System pref defaults — apply automatically unless overridden */
@media (prefers-reduced-motion: reduce) {
  :root:not([data-motion="normal"]) {
    --dur-micro: 0ms;
    --dur-page:  0ms;
  }
}

@media (prefers-contrast: more) {
  :root:not([data-contrast="normal"]) {
    --gr-85: #1A1A1F;
    --gr-70: #3B3B3F;
    --gr-50: #5D5D60;
    --stone: #B5B5B6;
    --gr-18: #89898A;
  }
}

/* Manual overrides */
[data-motion="reduced"] {
  --dur-micro: 0ms;
  --dur-page:  0ms;
}

[data-contrast="high"] {
  --gr-85: #1A1A1F;
  --gr-70: #3B3B3F;
  --gr-50: #5D5D60;
  --stone: #B5B5B6;
  --gr-18: #89898A;
}

[data-contrast="high"] .card,
[data-contrast="high"] .tag { border-width: 1px; }
[data-contrast="high"] :focus-visible { outline-width: 3px; }
[data-contrast="high"] .tag { background: transparent; border-color: var(--cobalt); }

/* Larger text — override specific classes */
[data-text="larger"] .t-body   { font-size: 19px; line-height: 30px; }
[data-text="larger"] .t-ui     { font-size: 17px; line-height: 24px; }
[data-text="larger"] .t-h3     { font-size: 24px; line-height: 32px; }
[data-text="larger"] .t-eyebrow { font-size: 13px; line-height: 18px; }
[data-text="larger"] .t-caption { font-size: 14px; line-height: 20px; }

/* Dark + high contrast combined */
[data-theme="dark"][data-contrast="high"] {
  --gr-85: #F5F5F0;
  --gr-70: #D8D8D3;
  --gr-50: #B0B0AC;
  --stone: #4E4E4C;
  --gr-18: #7E7E7B;
}

React hook — usePreferences

const KEYS = { theme: 'theme', text: 'text-size', contrast: 'contrast', motion: 'motion' };

export function usePreferences() {
  const [prefs, setPrefs] = useState(() => {
    if (typeof window === 'undefined') return defaults;
    const mq = window.matchMedia;
    return {
      theme:    localStorage.getItem(KEYS.theme)    ?? (mq('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'),
      text:     localStorage.getItem(KEYS.text)     ?? 'normal',
      contrast: localStorage.getItem(KEYS.contrast) ?? (mq('(prefers-contrast: more)').matches ? 'high' : 'normal'),
      motion:   localStorage.getItem(KEYS.motion)   ?? (mq('(prefers-reduced-motion: reduce)').matches ? 'reduced' : 'normal'),
    };
  });

  useEffect(() => {
    const root = document.documentElement;
    root.setAttribute('data-theme',    prefs.theme);
    root.setAttribute('data-text',     prefs.text);
    root.setAttribute('data-contrast', prefs.contrast);
    root.setAttribute('data-motion',   prefs.motion);
    Object.entries(prefs).forEach(([k, v]) => localStorage.setItem(KEYS[k], v));
  }, [prefs]);

  return [prefs, setPrefs];
}

07 — toggle UI

The accessibility menu.

One entry point, four toggles. Not scattered across the interface. Not hidden three levels deep. One button, one panel, four choices.

Entry point

  • Icon: Lucide Accessibility (stick figure with arms out). Standard convention — Apple, Google, and every major OS use variations of this icon. Alternate: Settings2 if the figure icon reads awkwardly in a portfolio context.
  • Placement: right side of desktop nav, between the theme toggle and the CTA. Bottom of the mobile drawer, above the theme toggle.
  • Size: 20px icon, --gr-70 color. Same visual weight as a nav link.
  • ARIA label: aria-label="Accessibility settings". Never "A11y" or icon-only in screen reader context.
  • Click behavior: opens a small panel anchored to the button, dismissible via Escape, click-outside, or a close button. Not a modal — modals interrupt reading flow.

Panel contents

ToggleLabelARIA label
ThemeDark modeSwitch to dark mode
TextLarger textEnable larger text
ContrastHigh contrastEnable high contrast
MotionReduce motionReduce motion and animation

Each row is a labeled switch, not a checkbox — switches communicate "on/off state" more clearly. Below the four rows, a Reset to system preferences text link that clears all four localStorage keys and returns to OS-level defaults.

08 — invariants

What does not change.

  • Layout. Grid, breakpoints, containers unchanged in any mode.
  • Voice. Copy is not simplified, softened, or shortened for accessibility modes. Users deserve the same content.
  • Navigation structure. Menu hierarchy is identical. Reduced motion does not remove menu items; larger text does not collapse to a simpler nav.
  • Information density. Case study tables, project grids, and content blocks show the same information. Larger text may require more scroll — that is correct, not a regression.
  • Interactive affordances. Buttons still look like buttons. Links still look like links. The visual grammar of clickability holds.
  • Cobalt as action color. Cobalt marks the same elements in every mode — links, CTAs, eyebrows, focus rings. Users learn the color once.
Why this matters

Accessibility modes that change layout, remove content, or simplify language treat disabled users as needing a lesser version of the site. The correct model is: same site, tuned for readability. Every user gets the full portfolio; the tuning changes how it presents, not what it says.
